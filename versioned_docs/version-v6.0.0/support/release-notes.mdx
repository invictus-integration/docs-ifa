# Release notes

<ReleaseNotes>

<ReleaseVersion version="6.4" date="July 2026">
  <Features>
    - **Simplify flow status filters into groups:** the flow status filters in the advanced search pane group statuses into broader categories instead of too detailed levels. 'Active' (= `Active`, `Resubmitted`, `Resumed` statuses). 'Error' (= `Failed`, `Resubmit Failed`, and `Resume Failed` statuses).
    - **[Transco] missing references no longer cause failures:** scenarios with conditional actions failed due to possible missing data references during instructions. The Transco no longer fails when `scopePath` or `destination` points to unavailable locations. The component logs a warning in case that happens to help spotting configuration issues.
    - **[Transco] fall back on default parameter values:** the component better handles optional or unavailable data. In situations where the component can't retrieve a parameter value from a path, you can fall back on a `defaultValue`.

    - **Dedicated Resource Groups for Private Endpoints:** Invictus now provides additional flexibility when deploying environments that use Virtual Network (VNET) integration. Private Endpoints can now be deployed into a dedicated resource group, allowing organizations to align deployments more easily with their networking, governance, and resource management standards.
  </Features>
  <TechChanges>
    - **Enhanced Private Network Deployment Support:** Invictus now offers an improved deployment model for environments that require private network connectivity. Deployments can now be configured to use Private Endpoints, ensuring that communication with underlying platform services stays within the private network boundary.
    - **Upgrade to .NET 10:** the Dashboard and Framework components run on .NET 10.
  </TechChanges>
  <Fixes>
    - **[ExceptionHandler] report error details in failed `ForEach` loops:** the component captures inner errors inside `ForEach` loops in Logic Apps workflows instead of displaying general error user messages. Users no longer have to switch to Azure to find the root cause for failures.
    - **Improved automatic recovery of deferred messages:** We have enhanced the automatic recovery mechanism for messages that remain in a deferred state for an extended period due to intermittent platform-related issues outside of Invictus' control.

      Previously, when a deferred message was automatically resubmitted, environments with multiple subscribers could receive the message more broadly than intended. The subscription filtering logic has now been improved to ensure that automatically resubmitted messages are routed only to the appropriate subscriber.

    - **Improved CosmosDB reliability during high-volume processing:** We've improved the way Invictus handles large numbers of background operations running at the same time. In certain scenarios, especially during initial setup or periods of high activity, this could result in database connection limitations that caused processing failures. The processing logic has been optimized to better manage concurrent operations, improving stability and reducing the likelihood of these errors occurring.
  </Fixes>
</ReleaseVersion>

<ReleaseVersion version="6.3" date="March 2026">

  <Features>
    - **Dashboard Gateway as proxy:** the Dashboard Gateway routes all workflow results through a central proxy. You can view them even when Logic Apps run in a private VNET.
    - **Admins can unlock accounts:** users with a *System admin* role can now unlock accounts directly in the Dashboard. Before this, it required a direct storage change.
    - **Swagger/OpenAPI spec restored:** the OpenAPI spec for the Invictus HTTP API's is active again. Set the `useOpenApi` Bicep flag to `true` during install to enable it. It's off by default.
    - **Search by property:** you can search for a message by one or more custom properties using the new advanced search pane.
  </Features>
  <TechChanges>
    - **Framework SDK update:** all components run on their most recent SDK version.
    - **Transco property naming fixed:** the Transco component now generates property names that follow the Invictus naming conventions.
    - **Application Gateway support:** Invictus works with an Application Gateway in front of the Dashboard. [Two new Bicep flags enable this](../dashboard/installation/?step=deploy&q=applicationgateway#bicep-template-parameters).
  </TechChanges>
  <Fixes>
    - **Tables missing on install:** the install again creates all required Azure Storage tables. Regression introduced in v6.2.
    - **Search filters not passed on:** all search filters carry over when you navigate from the Dashboard page to the Flows page.
    - **Flows load fail intermittently:** a race condition caused flows to fail on the first load. They now load reliably on the first attempt.
    - **Basic search ignores properties:** the basic search now returns results from message properties again.
    - **Wrong tooltip for Function App messages:** the tooltip for Azure Function messages incorrectly read 'Logic Apps'. It now reads 'Function Apps'.
  </Fixes>
</ReleaseVersion>

<ReleaseVersion version="6.2" date="February 2026">
  <Features>
    - **Dashboard shows 'Cancelled' Logic App runs:** the Dashboard now shows cancelled Logic App runs as 'Cancelled' instead of 'Succeeded'. This makes them quick to identify.
    - **Azure Function App traces in Dashboard:** the Dashboard now shows Azure Function App runs alongside Logic App traces. Startup and custom logs appear in a shared tree view. A new icon distinguishes Function App runs.
    - **Faster and clearer property filters:** the filters on the search page load faster and have a clearer layout.
    - **Toggle for resubmit and resume buttons:** you can enable or disable the resubmit and resume buttons in the advanced settings pane. They're off by default.
  </Features>
  <TechChanges>
    - **[Accident breaking] VNET renames:** these Bicep parameters have new names. This breaks installs by accident. Update your deploy file to use the new names:
      - `containerAppEnvironmentSubnetName` → `delegatedContainerAppEnvironmentSubnetName`
      - `disableStorageAccountPublicNetworkAccess` → `enableStorageAccountPublicNetworkAccess`
      - `vnetResourceGroupName` → `virtualNetworkResourceGroupName`
    - **Standard Service Bus SKU works with VNET:** Invictus no longer requires a Premium Service Bus SKU when deployed with VNET. A Standard SKU is enough. This lowers infrastructure costs for development and test environments.
    - **Optional resource locks:** a new `useResourceLocks` Bicep flag lets teams {/* vale Google.WordList = NO */}disable{/* vale Google.WordList = YES */} Azure resource locks at install time.
    - **Script to remove old Container App revisions:** a [new script](../../scripts/Invictus-RemoveOldRevisions.ps1) removes stale Azure Container App revisions. Run it after each install to keep your environment clean.
    - **Private endpoint naming follows conventions:** private endpoint names now use the `pep-` prefix instead of `conn-`, aligning with Azure naming conventions for private endpoints.
  </TechChanges>
  <Fixes>
    - **Full flow path not shown:** the Dashboard now shows the full folder path when you open a flow in a sub-folder.
    - **PubSub sets wrong workflow run ID:** the PubSub now writes the correct value to the `x-ms-workflow-run-id` header on outgoing messages.
    - **Azure Container Registry unreachable:** the install now waits for the private endpoint to be ready. It no longer creates the Azure Container Registry before the endpoint is ready.
    - **SequenceController fixes:** the `SequenceController` has two bug fixes:
      - a scaling issue that caused many timeout errors for `WaitForExecution`.
      - a new `retentionDays` flag stops the part from keeping state for too long.
    - **Cursor jumps when editing flow name:** the cursor no longer jumps to the end when you edit a flow name. It now stays where you left it.
    - **Access tokens written to logs:** the Dashboard no longer writes OAuth access tokens to the HTTP trace logs. This was a data exposure risk.
  </Fixes>
</ReleaseVersion>

<ReleaseVersion version="6.1" date="January 2026">
  <Features>
    - **Transco supports `strip-space`:** `Transco` now supports the `strip-space` XSLT directive. It removes whitespace-only text nodes from the XML input before transformation.
  </Features>
  <TechChanges>
    - **Bicep uses Azure Key Vault output URL:** Bicep templates now use the vault's own output URL instead of constructing a fixed value. This prevents mismatches in non-standard vault configurations.
    - **Set Azure Container Registry name:** a new `containerRegistryName` deploy parameter lets you provide your own Azure Container Registry name.
    - **Logic App detail link opens new designer:** the Logic App detail link in the Dashboard now opens the updated Logic Apps designer. The classic view is no longer used.
  </TechChanges>
  <Fixes>
    - **Expanded rows bleed across pages:** the Dashboard no longer restores expanded flow rows when navigating to a new page. Each page starts with all rows collapsed.
    - **Logic App run error not shown:** the Logic App detail page now always shows the error message for a failed run, even when the error originates from a child workflow.
    - **Missing Container App scaling rules:** all Container App scaling rules are now defined in Bicep and are individually configurable per component.
    - **Sign-in fails for users in large Entra ID groups:** users who belong to many Entra ID groups can now sign in. The issue occurred when the groups claim in the JWT exceeded the token size limit.
    - **RegexTranslator supports managed identity:** the `RegexTranslator` component now authenticates using managed identity. Connection string authentication is no longer required.
    - **PubSub messages get stuck in queue:** the PubSub Service Bus consumer now acknowledges messages correctly. Messages no longer remain locked and unprocessed in the queue.
  </Fixes>
</ReleaseVersion>

<ReleaseVersion version="6.0" date="November 2025">
  <Features>
    - **Audit log tracks group and flow changes:** the audit page now records group sync, and folder and flow add/remove events.
    - **Workflow column shows Logic Apps Standard site name:** the Workflow name column now includes the site name for Logic Apps Standard. This lets you tell flows apart when sites share the same workflow name.
    - **Transco returns a single column value:** `Transco` can now return a value from a single column, even when the query returns many rows. Set `columnName` in the Transco config to enable this. It's off by default.
    - **Managed identity for all Framework components:** all Framework components now authenticate using managed identity. See the [`identityProviderApplicationId`](../framework/installation/index.mdx?q=identityProviderApplicationId) Bicep parameter for setup details.
  </Features>
  <TechChanges>
    - **Move to Azure Container Apps:** the Dashboard and all Framework components now run on Azure Container Apps. See the [v6 upgrade guide](../support/migrate-v5-to-v6.mdx) for migration steps.
    - **Cosmos DB via managed identity:** Invictus now retrieves the Cosmos DB key at runtime using managed identity. A static connection string is no longer needed.
    - **Legacy PubSub, Transco, and Matrix API versions removed:** v6 removes the deprecated API versions of PubSub, Transco, and Matrix. New installs don't remove existing deployments of these versions automatically. Migrate to the current versions as soon as possible.
  </TechChanges>
  <Fixes>
    - **Flow column names ignore config casing:** column names in the Dashboard now use the casing defined in your flow config instead of always showing uppercase.
    - **Flow search ignores case:** flow search in the Dashboard now matches regardless of case.
    - **ExceptionHandler fixes:**
      - The `nextLink` parsing works.
      - The `siteName` is optional for Consumption Logic Apps.
      - The pattern for special characters handles edge cases.
      - The handler checks input and output links of repetition results.
      - The handler catches `Gateway Timeout` errors from Azure API Management.
  </Fixes>
</ReleaseVersion>

</ReleaseNotes>
