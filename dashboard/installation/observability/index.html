Fine-tune observability v6.5

Feature included since Invictus v6.5.

The Invictus product uses OpenTelemetry for observability. Default installations include pre-configured instrumentation, filtering, and sampling strategies. Fine-tune these options against your traffic and budget.

OpenTelemetry Collector sidecar​

An OpenTelemetry Collector sidecar runs in an Azure Container App alongside your Invictus installation. Collecting telemetry data and exporting it to Azure Monitor. The Collector reads its configuration from the OTelCollector-Config.yml file. Stored in the inv-${resourcePrefix}-otel-collector Azure File Share by default.

The default configuration works out of the box, but it includes placeholder values worth reviewing. They live in the bounded-sampling policy, part of tail_sampling in the traces pipeline. This policy limits how many trace spans get sent to Azure Monitor. It prioritizes errors and slow requests over successful ones.
